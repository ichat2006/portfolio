MALD & SWAD — AI Assistive Navigation

Python · YOLO · LiDAR · Jetson Nano · iOS (Swift / AVSpeechSynthesizer) · WebSocket

An assistive navigation device that fuses LiDAR depth with real-time object detection into spoken guidance, delivered through a companion iOS app. The hard part was getting sensor fusion, threading, and networking to cooperate on constrained embedded hardware, fast enough to be genuinely useful in real time.

View on GitHub
›Technical debrief

The project started with a friend, Henry, who's legally blind — I wanted something that could give someone a real-time read on the space around them. It runs on a Jetson Nano with an iOS companion app.

Concurrency

Two sensing threads run in parallel: a LiDAR thread that reads depth in a few milliseconds, and a YOLO thread that runs object detection (the dominant cost, roughly 50–100 ms with a lighter model variant and reduced input resolution). Each writes its latest result into a shared slot and blocks on a condition variable rather than busy-polling; a combiner thread waits until both are ready, fuses them, builds a message, and releases the sensing threads for the next cycle. That avoids the classic read-modify-write race without burning CPU on a spin loop. Python's GIL only lets one thread run bytecode at a time, but the blocking wait releases the GIL while idle and PyTorch releases it during heavy inference, so the pipeline gets real concurrency, and real parallelism where it counts.

Fusion & latency

LiDAR gives accurate depth with no semantics; YOLO gives identity with weak depth. Fused, each covers the other's blind spot. (Erratic-motion detection is inferred frame-to-frame from position deltas — there's no dedicated IMU chip, an honest correction from an earlier resume draft.) End to end the pipeline lands around 60–130 ms, comfortably under the 200 ms target.

Networking & output

The app talks to the device over a WebSocket on TCP, chosen over UDP on purpose: each message is a discrete safety instruction like “obstacle ahead, 2 meters,” so a dropped packet is a missed warning, not a frame you can skip. Output is a templated phrase — “There is a [class] [distance] ahead” — synthesized on-device with AVSpeechSynthesizer so speech never waits on the network, and the system deliberately says something even when detection is uncertain rather than going silent.

What I'd push further

TensorRT with FP16 on the Jetson, pinning the YOLO thread to a core to cut scheduling jitter, a real IMU (an MPU6050 over I²C) to replace the frame-to-frame motion inference, and per-thread stack tuning.

Team project — no public repo
›Technical debrief
Interview-style coursework

The first semester is built around interview-style problems. One was a satellite temperature monitor: a CMake C++ CLI with a thin-shell / fat-core split and redundant-sensor averaging that checks both range and cross-sensor agreement, so it catches two individually in-range readings that disagree with each other — a fault a naive range-only check misses. Another was an air-traffic-control tracker where tick() fuses a 50 Hz noisy radar and a 5 Hz accurate GPS transponder through a Kalman filter without blocking, using a shared std::atomic<Stamped> slot, per-sensor staleness detection, and graceful degradation — fall back to whichever sensor is still fresh, or predict from physics if both are stale, rather than freezing. Multi-sensor time alignment is handled with timestamp-based freshness checks instead of assuming synchronized clocks.

Autonomy subteam

On the Autonomy subteam I work on the behavior layer above a vehicle's low-level motion controller (Nav2 for ground vehicles), built on SPAR, the shared sim-portable runtime all three VIP tracks build on. It's a behavior tree — Fallback / Sequence and their reactive variants — that decides which behavior is active, handles interrupts like battery-low with correct priority ordering, and talks to a Tower-style operator interface over a shared wire protocol (pidgin), all validated in high-fidelity SIL simulation before anything touches real hardware.

NFL Stock Exchange

Built at AI ATL 2025 — turns live NFL games into a real-time stock market where team “shares” rise and fall with in-game performance. Every drive, score, and turnover moves prices instantly.

View on GitHub
›Technical debrief
Stack & concept

Full stack: React 18, TypeScript, and Tailwind on the front end; FastAPI, SQLAlchemy, and MySQL on the back end; deployed live on Railway during the hackathon. Team values update from live game state, so a comeback or a turnover reprices a team in seconds.

Modeling

ML models — XGBoost, gradient boosting, random forest, and logistic regression — forecast win probability and detect comeback scenarios in real time to enable flash bets, and I integrated the Kalshi API for real market data on team value and playoff probability. The prices themselves come from a custom mean-reversion algorithm that models consumer demand toward an organic equilibrium, recalculated every five seconds against live market forces.

Systems

Async background tasks drive the real-time price updates, and the trade endpoints are RESTful with authentication. The interesting engineering was keeping prices live and consistent while people traded against them, under real hackathon time pressure.

AAPL Return Forecaster

Python · Keras / TensorFlow · XGBoost · Ridge

A leakage-safe pipeline forecasting 10-day stock returns, benchmarking an LSTM against XGBoost and Ridge baselines. The real work here is the validation, not the model.

View on GitHub
›Technical debrief

The point of the project is validation discipline. It uses walk-forward validation with purged and embargoed gaps between train and test windows, which specifically prevents lookahead bias — information from the test period leaking into training through overlapping windows and inflating results in a way that quietly collapses on genuine out-of-sample data.

That's the subtle correctness bug that makes a model look great in a backtest and fail in the real world, so catching it is the actual skill on display — not whether an LSTM edges out XGBoost or Ridge. The baselines are there to keep the LSTM honest.
